# План: обновление профилей и подписок, адаптация (2026-11-05)

## 1. Диагностика кнопки Cloudflare
- Кнопка «Обновить свои профили Cloudflare» не скачивает файл по URL: она
  регистрирует WARP-личность (`https://api.cloudflareclient.com/v0a4471/reg`,
  тот же адрес, что в PC `nova-go/warp/register.go`) и запускает локальный
  сканер WARP-префиксов.
- На проверенной сети сканер вернул `0` подтверждённых точек: UDP-рукопожатия
  не отвечают. Поэтому сообщение «точки входа не найдены» — следствие сети, а не
  неверного адреса.
- Исправление: при пустом результате сканера брать точки входа из встроенного
  набора Nova (`warp_verified_seeds.json`), а не завершать выпуск ошибкой.
  Адаптация затем отбракует нерабочие.

## 2. Аддитивное хранение VLESS
- 4 источника из PC: iboxz, Delta-Kronecker REALITY, 0xRadikal, barry-far.
- `PublicSubscriptions` хранит состояние по каждому URL (ETag, Last-Modified,
  состав), обновляет только свой источник и не удаляет чужие профили.
- Поднять общий лимит профилей так, чтобы 4×120 + своя подписка помещались
  (800 вместо 400). Встроенные профили не заменяются.

## 3. Модуль и кнопка
- `ProfileUpdateCoordinator` — единая точка: списки маршрутизации + 4 публичные
  подписки; возвращает сводку.
- Новая кнопка «Обновить профили и подписки» в карточке
  «Выбор протокола/региона», выше кнопки Cloudflare.
- Кнопка Cloudflare остаётся для выпуска WARP-профилей; её выпуск теперь
  дополняет существующий набор.

## 4. Адаптация
- Запускается после обновления профилей и работает по полному набору
  (новые + встроенные).
- Нерабочие **сгенерированные** WARP-профили после прогона удаляются из
  `warp_generated.json`; встроенные семена остаются в APK, но получают
  статистику отказов и уходят вниз очереди.
- VLESS-профили проверяются существующим перебором при подключении; адаптация
  WARP их не трогает.

## 5. Проверка
- JVM-тесты на выбор источников, лимиты, аддитивность.
- Сборка release/debug, установка, проверка кнопок и логов на RMX3370.
- Обновление changelog/verification и релиз.
